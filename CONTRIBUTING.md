# Contributing

Read the [development guide](docs/development.md) before you change the code.
The repository uses GitHub issues and pull requests.

1. Describe the current behavior and the required behavior.
2. Include the OS, CLI version, and terminal layout for a defect.
3. Remove credentials and private conversation text from examples.
4. Add a regression test for changes to observable behavior.
5. Run the applicable checks.
6. Update the related guide and change record.
7. Open a pull request with the evidence.

Use the maintainer's configured Git identity for commits made on their behalf.
Do not add a generated assistant identity to the Git author or commit trailer.
Keep documentation within the [writing policy](docs/writing-policy.md).
Use the [pull request form](.github/pull_request_template.md) to record validation.
